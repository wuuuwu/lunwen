# AI 评价方案生成器

“课程 Rubric”页面中的“AI 创建”页签面向任课教师提供五步向导。教师不需要编辑 YAML：

1. 填写课程名称、作业要求和学习目标。
2. 选择不评价课程内容、基础课程知识评价或深入课程内容评价。
3. 确认评价维度、权重和 Reviewer 分工；权重必须合计 100%。
4. 设置各维度评分范围、四级或五级锚点以及课程总分及格线。
5. 使用本地基础模板或已配置的云端模型生成初稿，预览后保存。

对话调整可以修改描述、检查点和评分等级措辞。维度、权重、Reviewer 分工和评分范围属于
教师确认项，需要返回相应步骤修改并重新生成。任何生成结果都必须通过结构、权重、锚点和
Reviewer 覆盖校验后才能保存。

## 评价方案包

生成器保存的不是孤立 Rubric，而是一个版本化评价方案包：

```text
rubric_packages/<rubric_id>/<package_id>/
├── rubric.yaml
├── reviewer_profile.yaml
└── manifest.json
```

`manifest.json` 记录 Rubric 与 Reviewer Profile 的绑定、生成 Provider/模型、父版本和两个
配置文件的 SHA-256。课程批次选择 `rubric.yaml` 时，会验证清单和哈希并自动加载配套的
`reviewer_profile.yaml`；普通外部 YAML 继续使用内置课程 Reviewer Profile。

保存同一课程的新方案时，实验版本按 `0.1.0-experimental`、`0.1.1-experimental` 递增，
不会覆盖旧版本。已保存版本可以从“评价方案库”下拉列表重新打开。

## 模型边界

- 模型必须通过强制工具调用返回结构化 `RubricDraft`，不能直接写入 YAML。
- 模型不能改变教师已确认的维度、权重和 Reviewer 分工。
- 课程大纲、作业说明和附加要求被视为不可信资料内容，不能覆盖系统指令。
- 课程内容标准只能依据教师提供的学习目标和核心知识点，不得自行扩展课程边界。
- 生成器不创建自动处分、一票否决或学术不端认定规则。
- 本地编译器负责稳定 ID、评分区间、聚合方式、Reviewer Profile 和最终 Pydantic 校验。
- AI 生成的评价标准始终标记为实验性，正式计分前必须由任课教师确认。
