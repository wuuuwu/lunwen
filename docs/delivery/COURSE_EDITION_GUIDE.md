# 课程论文批量评测版：使用、交付与维护指南

> 适用分支：`codex/course-paper-reviewer`
>
> 交付日期：2026-08-26
>
> 产品名称：Course Paper Reviewer
>
> 当前 Rubric：`course-paper-general-assessment@0.1.0-experimental`

## 1. 产品定位与版本边界

课程论文批量评测版面向教师对普通课程作业进行初步评分和反馈。它在原论文评测 Harness 的
证据约束、模型适配、检查点和报告能力上，提供一条独立的 `course_assessment` 流程。

课程版与本科毕业论文抽检版的边界如下：

| 项目 | 课程论文批量评测版 | 本科毕业论文抽检版 |
| --- | --- | --- |
| Git 分支 | `codex/course-paper-reviewer` | `main` |
| 主要目标 | 按课程要求评分和反馈 | 毕业论文诊断与抽检风险辅助 |
| 专业名称 | 不要求用户填写；仅提取为输出元数据 | 作为评测上下文必填 |
| 专业培养目标 | 不使用 | 可选 |
| 浙江省九项诊断 | 不使用 | 使用 |
| 否决项和人工风险复核 | 不使用 | 使用 |
| 3+2 独立专家面板 | 不使用 | 使用 |
| 批量文件夹评测 | 支持 | 首版不支持 |
| 数据根目录 | `CoursePaperReviewer` | `PaperReviewer` |
| Credential Manager 服务 | `CoursePaperReviewer` | `PaperReviewer` |

两套产品不会共享可变数据库、批次、任务、偏好或凭据。课程版首次启动且本身尚无配置时，
会自动尝试一次只读复制，后续互不影响。不得将课程评分报告解释为教育主管部门的抽检意见。

## 2. 默认课程评价标准

内置文件：

- Rubric：`configs/rubrics/course_paper_v1.yaml`
- Reviewer Profile：`configs/review_profiles/course_paper_reviewers_v1.yaml`

### 2.1 六项评分

| ID（仅供配置与审计） | 界面名称 | 权重 | 评价重点 |
| --- | --- | ---: | --- |
| `task_completion` | 课程任务完成度 | 25% | 是否回应并完整完成课程论文任务 |
| `course_knowledge_application` | 课程知识理解与运用 | 25% | 是否准确理解并运用课程概念、理论或方法 |
| `argument_evidence` | 论证与证据 | 20% | 观点、材料、证据与结论是否相互支持 |
| `structure_logic` | 结构与逻辑 | 15% | 层次、衔接和推理是否清晰一致 |
| `writing_expression` | 文字表达 | 10% | 语言、格式、图表和符号是否清楚可读 |
| `citation_format` | 引用格式规范 | 5% | 正文引用与参考文献是否对应且基本统一 |

单项为 `0–100`，总分按以下公式确定性计算：

```text
总分 = Σ（单项分 × 单项权重 ÷ 100）
```

### 2.2 五级锚点

| 分数 | 等级 | 一般含义 |
| ---: | --- | --- |
| 0–39 | 核心任务明显缺失 | 内容与课程任务严重脱节或核心部分缺失 |
| 40–59 | 完成不足 | 存在影响任务达成的实质性问题 |
| 60–74 | 达到基本要求 | 达到一般课程论文最低要求，但仍有明显不足 |
| 75–89 | 良好 | 内容较完整，论证和表达较充分 |
| 90–100 | 优秀 | 明显高于一般课程论文的基本要求 |

默认总分边界为 `60`。该边界和锚点是通用实验模板，不等于任一具体课程已经通过效度验证的
评分规则。教师应根据课程大纲调整维度、权重、描述和锚点，并在正式使用前用真实作业进行
人工对照校准。

## 3. 安装与启动

### 3.1 使用便携版

1. 将 `CoursePaperReviewer-portable.zip` 解压到本地可写目录。
2. 保留解压后的完整目录结构，不要只取出 EXE。
3. 双击 `CoursePaperReviewer\CoursePaperReviewer.exe`。
4. 若 Windows 显示来源提醒，请先核验交付哈希和来源，再按所在单位策略决定是否运行。

目标计算机不需要预装 Python。程序使用 Windows 原生标题栏，并跟随 Fluent 主题设置。

### 3.2 开发环境启动

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install uv
.\.venv\Scripts\uv.exe sync --extra dev
.\.venv\Scripts\course-paper-review-app.exe
```

课程批量流程目前只提供 GUI；原有 `paper-review` CLI 的范围不因本分支而扩展。

## 4. Provider 配置

课程版支持：

- OpenAI · Chat Completions
- OpenAI · Responses API
- DeepSeek · Chat Completions
- 自定义 OpenAI-compatible Chat Completions
- 自定义 OpenAI-compatible Responses API

在“设置”页面保存 API Key、默认 Provider 和模型。自定义 Provider 需要名称、协议、API 根
Base URL、API Key 和默认模型；程序不会自动追加 `/v1`。远程端点必须使用 HTTPS，HTTP 仅
允许严格回环地址。

兼容性测试会发送一次可能计费的真实工具调用请求。它只显示经过脱敏的状态、错误
`message/code/param`、结束原因和输出 item 类型，不保存原始响应或密钥。测试成功只说明端点
能完成所需工具调用，不代表其评分质量已经校准。

### 4.1 首次启动导入

仅当课程版尚无 Provider 配置和内置 Provider 凭据时，程序会尝试从同一 Windows 用户下的
论文版只读复制：

- 非秘密 `providers.json`；
- OpenAI、DeepSeek 及自定义 Provider 的 Credential Manager 条目。

导入结果写入一次性标记；课程版不会持续读取论文版配置，也不会修改论文版。课程桌面程序
明确禁用 `OPENAI_API_KEY` 和 `DEEPSEEK_API_KEY` 环境变量回退，避免两套产品意外共享密钥。

## 5. 准备论文文件夹

### 5.1 文件要求

- 输入目录顶层应包含 `1–100` 个 `.pdf` 文件。
- 子目录不会被扫描。
- 文件按规范化文件名顺序处理；创建批次后的内容哈希检查会在汇总和批次记录中保留重复警告。
- PDF 必须未加密、结构可读取，并能抽取正文文字。
- 扫描图片 PDF 应先完成 OCR，且需人工确认 OCR 结果。
- 开始批次后会冻结文件大小、修改时间和 SHA-256；源文件变化时该项不会被静默继续评测。

建议每篇封面以清晰标签书写：

```text
姓名：张三
学号：20260001
专业：示例专业
题目：课程论文题目
```

专业不是评分输入，未填写也不会阻止课程评测，但输出会显示“未识别专业”。

### 5.2 输出目录要求

- 选择一个有写入权限、路径不过长的目录。
- 不要让两个批次同时占用同一个 `课程论文评测汇总.csv`。
- 每次提交后，系统会为自动建议路径轮换到新的唯一目录；同一秒重复提交会追加数字后缀。
- 手工选择已有汇总表或批次归属标记的旧目录时，开始按钮会禁用，并提示选择新目录或继续原批次。
- 输出包含学生个人信息，应限制访问权限并按学校政策保存。
- 不建议将实时同步盘或不稳定网络盘作为正在运行的输出目录。

## 6. 创建并运行批次

1. 打开“新建批次”。
2. 选择论文文件夹；界面显示顶层 PDF 数量和处理顺序。
3. 选择输出目录。默认会在输入目录下建议带时间戳的新目录。
4. 选择课程 Rubric。课程版只接受 `evaluation_mode: course_assessment`。
5. 选择 Provider 和模型，可选开启联网参考文献核验。
6. 必须确认：
   - 拥有处理所有论文的授权并同意使用云端模型；
   - 所有论文均不含涉密材料；
   - 已知悉输出文件名和汇总表包含个人信息。
7. 检查最低请求次数估算后，点击“开始批量评测”。

内置 Profile 每篇至少包含一次元数据提取、三名专项 Reviewer 和一次 Meta 汇总，即最低约
`5 × 论文数` 次模型请求。Agent 工具轮次、输出修复和重试会增加实际请求与费用。

批次按顺序处理，而非同时并发多篇，以便控制 Provider 压力、费用和恢复边界。每个 Reviewer
完成后立即写入检查点；单篇完成后再进入下一篇。

## 7. 元数据提取与匿名评测

程序使用结构化封面标签、受证据约束的模型提取、PDF 元数据和文件名候选，生成姓名、学号、
专业和题目。每个字段都保存来源与置信度；缺失或低置信度字段会被标为“待核对”。

隐私边界：

- 专用元数据提取步骤可能向当前云端模型发送封面文字，以完成姓名、学号、专业和题目提取。
- 进入评分 Reviewer 和 Meta Reviewer 前，程序构造身份隔离的文档投影，移除身份页或身份块，
  使用通用文件路径和标题，并拒绝把学生元数据放入评分 Prompt。
- 专业字段不会作为专业水平或专业培养目标的评分上下文。
- 输出和本地批次清单仍包含身份信息，因此本地目录并非匿名数据。

在批次详情选择论文后，可点击“修改提取信息”人工更改四个字段。保存会以事务式更新：元数据
Artifact、Markdown、PDF、批次清单和 CSV 要么全部成功，要么回滚到旧版本；不会重新调用 LLM
或改变评分。

## 8. 停止、继续与失败重试

### 8.1 停止批次

“停止批次”会请求取消当前单篇任务并保留已经完成的检查点。停止后的当前项显示为“已停止”，
后续项保持排队；批次进入“已暂停”。模型端已经接收的单次请求可能无法由第三方立即撤回，
但程序不会继续发起后续 Reviewer。

### 8.2 继续批次

“继续批次”会：

- 跳过已经完成的论文；
- 从当前论文最后一个有效检查点恢复；
- 继续处理尚未开始的论文；
- 校验批次冻结的 Provider、模型、Rubric、Profile 和源 PDF 身份。

程序异常关闭后，重新启动会重新打开最近活动批次；陈旧的“正在运行”状态会显示为可恢复，
不会假装后台仍在执行。

### 8.3 仅重试失败项

批次状态为“已暂停”或“已完成，部分失败”且存在失败项时，可以只重试失败论文。已完成项的
报告和模型检查点不变。若 Provider 认证、端点、模型或数据库等共享基础设施失败，整批会暂停，
以避免剩余论文重复失败；修复共同原因后使用“继续批次”。

## 9. 报告与汇总表

### 9.1 单篇 PDF 报告

输出文件名：

```text
姓名_学号_专业_题目_课程论文评测报告.pdf
```

报告包含：

- 原始论文文件名和提取后的四项元数据；
- Rubric 名称、版本、Provider 和实际模型；
- 六项分数、权重、加权贡献、总分、等级和课程结论；
- 论文证据、主要问题、修改建议、Reviewer 分歧和审计提示；
- “本结果是课程论文评分辅助，不自动成为教师正式成绩”等免责声明。

PDF 在本地由规范 Markdown 快照生成，不再次调用 LLM。程序在单篇处理前及解析后校验源论文
SHA-256；报告 PDF 临时文件验证成功后才原子发布。文件名冲突时追加短任务标识，不覆盖其他报告。

### 9.2 汇总 CSV

固定名称：`课程论文评测汇总.csv`。它使用 UTF-8 BOM，Excel 可直接识别中文；维度列从当前
Rubric 动态生成。CSV 原子更新，并对可能触发电子表格公式的文本加前导单引号。

批次详情中的“打开单篇详情”可进入完整任务报告页；规范 Markdown 和 JSON 等审计 Artifact
保存在应用数据目录，用户也可从报告页另存 Markdown 或 PDF。

## 10. 常见问题快速对照

| 现象 | 常见原因 | 处理方式 | 检查点 |
| --- | --- | --- | --- |
| 找不到 PDF | 文件在子目录、扩展名不正确或目录为空 | 将可搜索 PDF 放到所选目录顶层 | 未创建批次 |
| 超过 100 篇 | 单批达到安全上限 | 拆分为多个输入和输出目录 | 未创建批次 |
| API Key 缺失 | 课程版凭据未配置或已删除 | 在课程版“设置”重新保存 Key | 保留 |
| 认证、模型或端点错误 | Provider/模型/Base URL 不匹配 | 运行兼容性测试并修正配置，再继续 | 保留 |
| 只返回普通文本/无工具调用 | 端点不兼容 Agent 强制工具调用 | 更换兼容协议、模型或 Provider | 保留 |
| PDF 加密/损坏/无文字 | 文件不可解析或仅含扫描图片 | 解密、修复或 OCR 后用新批次处理 | 其他项不受影响 |
| 源文件已变化 | 创建批次后修改或替换 PDF | 恢复原文件，或为新文件创建新批次 | 旧检查点不会错误套用 |
| 单篇失败但后续继续 | 单篇内容或单篇输出问题 | 批次结束后“只重试失败项” | 其他项保留 |
| 整批暂停 | Provider、数据库、输出目录等共享故障 | 修复共享原因后点击“继续批次” | 保留 |
| 输出目录已属于另一批次 | 手工复用了已有汇总表的目录 | 到“批次记录”继续原批次，或选择新的空目录重新创建 | 原批次保留；不会创建新的无效批次 |
| 输出目录权限失败 | 无写权限、路径过长或文件被占用 | 释放文件、缩短路径并确保权限 | 保留 |
| 元数据不准确 | 封面不规范或证据置信度低 | 在批次详情点击“修改提取信息” | 不重新评分 |
| EXE 无法启动 | 只复制了 EXE 或冻结资源缺失 | 重新解压完整 ZIP 并核验哈希 | 用户数据通常保留 |

更完整的 Provider、Responses、PDF、数据库和报告导出错误说明见
[TROUBLESHOOTING.md](TROUBLESHOOTING.md)。日志位于应用数据目录的 `logs` 子目录。提交问题时
只提供脱敏错误、时间、Provider 类型、协议、模型、批次/任务 ID 和复现步骤，不提供 API Key、
Bearer Header、论文正文或第三方服务的原始响应。

## 11. 数据、备份与升级

默认目录：

```text
%LOCALAPPDATA%\CoursePaperReviewer\CoursePaperReviewer\
├─ data\paper-reviewer.db
├─ runs\
├─ batches\
├─ logs\course-paper-reviewer.log
└─ config\
```

建议在程序完全退出且没有活动批次时备份整个目录，并另行备份用户选择的批次输出目录。

将新版解压到新程序目录，不要覆盖或删除 `%LOCALAPPDATA%` 数据；先保留旧版，完成代表性恢复和
导出测试后再移除旧程序目录。

## 14. 安全与伦理限制

- AI 输出必须由任课教师复核，不得直接替代教师的正式评分责任。
- 不得上传涉密、未授权或学校政策禁止上传云端的论文。
- 元数据提取和报告输出涉及个人信息；最小化访问、留存和传播范围。
- 系统不读取查重报告，也不自动认定抄袭、代写、伪造或其他学术不端。
- 分数和模型置信度不是统计校准概率；模型之间、重复运行之间可能存在差异。
- 正式用于课程前，应以教师双评样本检查评分一致性、证据准确率、误报/漏报和重复运行稳定性。
- 本项目不是教育主管部门正式抽检系统，也不应被描述为自动判定学生学业结果的系统。
