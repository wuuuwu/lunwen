# Paper Reviewer 常见问题与报错对照

本文只覆盖桌面端和常规 CLI 使用中最常见、可由用户处理的问题。界面可能同时显示一个简短提示和任务 ID；以下处理不要求提供 API Key、Bearer Header、论文正文、查重报告或 Provider 原始响应。

## 提交问题前的安全检查

请先记录以下不敏感信息：软件版本、Windows 版本、任务 ID、界面完整提示、Provider 的显示名称和协议、模型名称、Rubric 文件名、任务状态，以及是否启用了外部检索。不要复制请求头、完整 URL、请求体、响应体或论文文本。

桌面端日志目录可以通过“帮助”→“打开日志目录”或“设置”→“打开日志目录”打开，默认是 `%LOCALAPPDATA%\PaperReviewer\PaperReviewer\logs`。任务级事件和检查点位于 `%LOCALAPPDATA%\PaperReviewer\PaperReviewer\runs\<RUN_ID>`；日志文件和 `trace.jsonl` 的用途不同，应用日志不一定包含每个评测事件。

## 1. EXE 无法启动、窗口空白或资源缺失

**提示特征**：双击无窗口；弹出资源、Qt 平台插件或 DLL 缺失；窗口打开但图标、Rubric 或页面异常。

**场景与原因**：只复制了 `PaperReviewer.exe`，没有解压或保留整个 `PaperReviewer` 目录；安全软件隔离了 Qt 插件；便携目录被移动后部分资源丢失。

**处理**：重新解压完整 ZIP 到新的本地目录；确认 EXE 与其同级资源目录、Qt 平台插件和配置文件都存在；不要从压缩包内直接运行；必要时将目录加入可信位置后重试。不要下载或替换来源不明的 DLL。

**可恢复性**：通常可恢复。若没有成功创建任务，不涉及检查点。

**查看位置**：若应用能启动，打开日志目录；若完全不能启动，记录 Windows 弹窗文字和 EXE 目录结构，不要上传整个目录。

**求助信息**：EXE 版本/文件哈希、Windows 版本、完整但不含路径中个人信息的错误文字、是否完整解压。不要提供凭据或论文文件。

## 2. `No module named ...` 或开发环境依赖缺失

**提示特征**：命令行出现 `No module named aiosqlite`、`pymupdf`、`PySide6` 或其他模块名。

**场景与原因**：使用了错误的 Python 解释器；虚拟环境未创建、未激活或依赖同步未完成。这个错误通常发生在开发环境，不应出现在完整便携 EXE 中。

**处理**：在项目目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install uv
.\.venv\Scripts\uv sync --extra dev
```

随后使用 `.venv\Scripts\paper-review...` 或 `.venv\Scripts\paper-review-app.exe`，不要混用系统 Python。若是发布 EXE，重新获取完整便携包，不要向 EXE 目录随意复制单个 `.py` 或 `.whl`。

**可恢复性**：开发环境依赖问题可恢复；不会生成有效的评测检查点。

**查看位置**：终端中使用 `python -c "import sys; print(sys.executable)"` 确认解释器；发布包问题查看日志目录（若能启动）。

**求助信息**：Python 版本、`sys.executable` 的文件名、缺失模块名、执行的安装命令和退出码。不要发送环境中的 Key 或论文。

## 3. API Key 缺失或 Credential Manager 失败

**提示特征**：新建评测按钮不可用；提示“所选 Provider 未配置 API Key”“未配置 API Key”或“恢复任务所需的 API Key 不存在”；设置页无法保存、读取或删除 Key。

**场景与原因**：Key 尚未保存；选择了错误 Provider；Windows Credential Manager 被策略禁用、读取失败；自定义 Provider 的 Key 已显式删除；旧任务的快照端点/协议与当前凭据不匹配。

**处理**：打开“设置”，确认 Provider 和协议后重新输入并保存 Key；OpenAI Chat 与 OpenAI Responses 都使用“OpenAI” Key；自定义 Provider 需要在对应配置中重新输入 Key。确认后回到“新建评测”并刷新 Provider。不要把 Key 填入 Rubric、模型名、论文或报告。

**可恢复性**：已创建且有检查点的任务通常可恢复；缺 Key 时系统应在改变任务状态前拒绝恢复。补回同一 Provider/端点所需 Key 后重试。

**查看位置**：设置页错误 Message Bar、应用日志目录和任务 ID。不要从凭据库导出内容。

**求助信息**：Provider 显示名称、协议、任务状态、是否为新建或恢复、脱敏后的界面提示。不要提供 Key、账户信息或原始请求。

## 4. Provider 认证、Base URL、模型或权限错误

**提示特征**：兼容性测试显示“Provider 认证失败”“Provider 未找到接口或模型”“Provider 拒绝访问”“Base URL ...”；评测失败且状态为需要处理。

**场景与原因**：Key 无效或无权限；模型名称拼写错误/账号无权使用；Base URL 填成了具体 `/responses` 或 `/chat/completions` 路径；远程地址不是 HTTPS；自定义 Provider 选错 Chat/Responses 协议。

**处理**：在服务商控制台确认模型名、账号权限和接口根路径；Base URL 只填 API 根路径，例如 `https://example.com/v1`，不要让程序自动猜测版本路径；远程地址改为 HTTPS；自定义 Provider 的协议不支持原地修改，需要点击“更换端点/协议”创建新配置。保存后重新测试。

**可恢复性**：配置问题可恢复。失败任务的已完成检查点一般保留，修正 Provider/Key 后可恢复；不要删除旧 Provider 快照或任务目录。

**查看位置**：兼容性测试框中的脱敏 `message/code/param` 和响应诊断；应用日志和任务错误不应被视为自动完成脱敏，提交前只摘录人工确认过的非敏感摘要。

**求助信息**：Provider 显示名称、协议、模型名、HTTP 状态码、脱敏字段和任务状态。不要提供完整 Base URL（如其中含租户或密钥）、请求头或原始响应。

## 5. Provider 请求超时、连接失败或速率限制

**提示特征**：出现“Provider 请求超时”“无法连接 Provider，请检查 Base URL 和网络”或“Provider 已达到速率或额度限制”。

**场景与原因**：网络不可达、服务商临时故障、代理/防火墙阻断、模型响应过慢或额度/速率达到上限。

**处理**：确认浏览器或服务商状态页可访问；检查电脑时间、网络和代理策略；减少同时运行任务；稍后从任务记录“恢复评测”。不要在短时间内反复点击“开始评测”，以免产生重复请求或费用。

**可恢复性**：连接、超时和速率限制通常可恢复；系统会保留已完成阶段。认证、参数和模型错误不会靠重复重试解决。

**查看位置**：应用日志、任务 `trace.jsonl` 的事件摘要和任务状态。不要上传完整 Trace。

**求助信息**：任务 ID、Provider 名称/协议、模型名、提示类型、发生时间和是否稍后恢复成功。不要提供请求内容或 Key。

## 6. Responses API 状态、截断或只返回普通文本

**提示特征**：兼容性测试显示 `response.status`、`incomplete_details.reason`、`finish_reason`、output item 类型和“仅返回普通文本：是”；测试失败并提示没有产生所需 Agent 工具调用；评测中出现 Responses API 状态错误或输出不完整。

**场景与原因**：服务商没有真正实现 Responses API；返回 `failed`、`cancelled`、`queued` 或未完成状态；`incomplete_details.reason` 为 `max_output_tokens` 或 `content_filter`；服务商只返回 message/text，没有 function call；工具参数或协议结构不兼容。

**处理**：先确认设置中选择的是“OpenAI · Responses API”或自定义“Responses API”，不要用 Chat 端点冒充 Responses；确认 Base URL 是 API 根路径且服务商声明支持 `/responses`、工具调用和所选模型。若输出被 `max_output_tokens` 截断，更换支持结构化工具调用的模型或调整服务商侧限制；若只返回普通文本，改用支持 function tool calling 的 Provider/模型。程序不会静默把 Responses 请求改发到 Chat。

**可恢复性**：端点、协议和模型修正后，已有检查点可按桌面端恢复；只返回普通文本造成的 Agent 输出失败通常需要从失败任务恢复，不应重复创建多个任务。

**查看位置**：兼容性测试结果中的脱敏字段和响应诊断；应用日志与任务事件只提供摘要。诊断不包含响应正文。

**求助信息**：协议、模型名、`response.status`、`incomplete_details.reason`、`finish_reason`、output item 类型、是否普通文本和任务状态。不要提供 `response.output`、加密 reasoning、Authorization 或论文正文。

## 7. PDF 无法解析、加密或没有可搜索文本

**提示特征**：选择论文后提示 PDF 不存在/无效；评测失败并显示 PDF 打开错误、没有页面，或“PDF appears to be scanned or contains too little searchable text; OCR is not enabled”。

**场景与原因**：文件损坏、扩展名不是 PDF、PDF 加密需要密码、只有图片没有文字层、页数为零或文本太少。

**处理**：用可信 PDF 阅读器打开并另存为可正常打开的 PDF；确认文本可以选择和复制；对扫描件先在线下 OCR，再导入新的可搜索 PDF；移除密码保护时遵守论文处理授权和学校政策。不要把 OCR 结果直接当作无误，先抽查页码和文字。

**可恢复性**：输入文件问题通常可恢复，但失败前不会产生有效 AI 评测结果；若任务已建立解析检查点，使用修正后的输入通常应新建任务，以保留原文件哈希审计链。

**查看位置**：任务详情事件、应用日志和任务目录中的文档检查点（若已生成）。

**求助信息**：PDF 页数、是否可复制文字、是否加密、错误提示和任务 ID。不要发送论文文件、正文截图或未脱敏 PDF。

## 8. Rubric YAML、权重、Schema 或 Reviewer Profile 校验失败

**提示特征**：界面显示“Rubric 校验失败”、字段附近显示错误；CLI `rubric validate` 或 `profile validate` 失败；提示权重不为 100、Schema 不支持、未知字段、维度未覆盖或 Reviewer 配置不完整。

**场景与原因**：YAML 缩进/类型错误；Schema v2 使用了未知字段或不支持版本；评分 Rubric 权重不合计 100；维度没有锚点/检查项；v2 分组未完整覆盖维度；Reviewer Profile 没有覆盖所有维度；浙江双层评测缺少 5 个专业 Reviewer 或独立专家面板配置。

**处理**：先复制一份 YAML 再修改；使用内置配置作为结构参考；逐项修复界面给出的字段路径和错误，不要把内部 ID 改成报告中的中文标题。CLI 可执行：

```powershell
.\.venv\Scripts\paper-review rubric validate path\to\rubric.yaml
.\.venv\Scripts\paper-review profile validate path\to\profile.yaml
```

Schema v2 需要政策来源、`dual_advisory`、`weighted_rating`、离散 0–4 评分、3+2 面板、结构化否决项和实验性效度提示；`passing_score` 必须为空。自定义 Rubric 通过后再在桌面端重新选择并查看预览。

**可恢复性**：配置校验失败时不会启动云端请求，也不会修改现有任务。修正后可重新选择；已有任务使用创建时的 Rubric 快照，不会被当前 YAML 静默改写。

**查看位置**：Rubric 预览和字段错误；CLI 终端；应用日志。不要提交含论文内容的上下文或完整数据库。

**求助信息**：Rubric 文件名、Schema 版本、错误字段路径、权重总和、Profile 文件名和是否为内置配置。不要提供论文和 API Key。

## 9. 外部学术检索失败

**提示特征**：任务事件显示外部证据不可用、检索超时或来源失败；报告出现参考文献需人工核查、不可用或冲突警告，但评测仍继续。

**场景与原因**：网络受限、公共搜索服务限流、DDGS/OpenAlex/Crossref/arXiv 临时不可用、参考文献元数据不完整。

**处理**：检查网络；在新建评测中关闭“外部检索”只会停用 DDGS、OpenAlex、Crossref、arXiv 和参考文献自动核验，不会停用云端模型请求；若选用本机回环 Provider，只会连接本机端点。若需要文献证据，稍后从任务记录恢复或重新运行。人工核查报告中的 DOI、题名、年份和页码，不要把“未检索到”解释为“文献不存在”。

**可恢复性**：通常可恢复。外部检索故障一般只留下报告警告，不应抹掉已完成论文解析和模型评分检查点。

**查看位置**：任务事件、报告中的外部证据/参考文献核验部分、`reference-checks.json`（若已生成）和应用日志。

**求助信息**：任务 ID、是否启用外部检索、失败来源类别、时间和报告警告。不要提供论文参考文献全文或任何 Key。

## 10. `agent did not produce valid output within its budget`

**提示特征**：任务详情显示“任务失败：agent did not produce valid output within its budget”或类似“模型输出未通过结构化校验/预算耗尽”。

**场景与原因**：模型没有按要求输出有效结构化工具结果；只返回普通文本；工具参数 JSON 无效；模型在有限轮数、工具调用数或输出 Token 预算内没有完成；Responses continuation 或服务商 function calling 不兼容。

**处理**：先用“测试兼容性”确认 Provider 能产生指定工具调用；检查模型名、协议和 Rubric/Reviewer Profile 是否匹配；对自定义 Provider 确认其确实支持工具调用，不要只支持普通聊天。等待限流恢复后，在任务记录中点击“恢复评测”，不要并行创建重复任务。若同一模型反复失败，可在确认协议兼容后选择另一个支持结构化输出的模型。

**可恢复性**：通常可以从最近成功检查点恢复；已完成 Reviewer 不会重复调用。若模型始终无法输出结构化结果，则需更换模型/Provider，不能仅靠重复点击解决。

**查看位置**：任务详情的失败阶段、技术详情、应用日志和 `trace.jsonl` 事件摘要。运行错误与 worker traceback 不应被视为已完成脱敏；不要上传模型原始输出、Prompt、论文正文或 Authorization。

**求助信息**：任务 ID、失败阶段、Provider 协议、模型名、兼容性测试的脱敏诊断、是否恢复过及结果。不要提供 Key 或原始响应。

## 11. 取消评测无响应或恢复失败

**提示特征**：点击“取消评测”后按钮显示“正在取消…”；状态暂时未变；恢复按钮不可用或恢复后又失败。

**场景与原因**：当前请求尚在等待网络返回；后台线程正在安全关闭；应用没有真正结束任务线程；任务已进入报告或待人工复核状态；检查点缺失/损坏或 Provider Key 不再可用。

**处理**：等待界面完成安全停止，不要重复点击；确认对话框选择“确定”。取消完成后到任务记录确认“评测已取消”，再点击“恢复评测”。若恢复提示 Key 缺失，先在设置中补回同一 Provider；若提示检查点问题，保留任务目录和日志供开发者诊断。待人工复核任务不属于运行中任务，没有取消按钮，应在报告页处理待办。

**可恢复性**：取消本身通常可恢复，已完成检查点会保留；检查点损坏、快照不完整或 Provider 不可用时可能只能保留报告/证据并新建任务。

**查看位置**：任务记录状态、任务详情事件、任务目录 `trace.jsonl`、应用日志。不要删除任务目录再尝试恢复。

**求助信息**：任务 ID、取消前后的状态、已完成阶段、恢复提示和是否看到“已完成检查点仍然保留”。不要发送论文或密钥。

## 12. 数据库或任务记录加载失败

**提示特征**：任务记录显示“加载失败”、数据库错误、任务不存在、报告与任务状态不一致或应用启动后列表为空。

**场景与原因**：数据库文件被占用/锁定、权限不足、数据库与 `runs` 目录不是同一份备份、升级中断或任务目录/数据库文件被手工移动。

**处理**：退出其他 Paper Reviewer 进程，确认 `%LOCALAPPDATA%\PaperReviewer\PaperReviewer\data` 可写；不要直接编辑 SQLite。若使用备份，恢复 `data` 与整个 `runs` 目录的对应版本；重新打开应用并刷新任务记录。若只有报告文件，直接打开 `report.md`，不要将其当作可恢复任务。

**可恢复性**：数据库锁定通常可恢复；数据库损坏或备份不匹配需要从一致备份恢复。不要运行会覆盖原数据库的清理命令。

**查看位置**：`data\paper-reviewer.db`、`runs\<RUN_ID>`、应用日志和任务 ID。保留原文件副本再求助。

**求助信息**：错误类别、任务 ID、是否刚升级/迁移、数据库和任务目录是否来自同一备份、应用日志中的脱敏摘要。不要上传数据库、论文或凭据库；如需文件分析，应先获得明确授权并按学校数据政策处理。

## 13. Markdown/PDF 导出失败

**提示特征**：显示“仅已生成报告的任务可以导出”“目标文件已存在”“导出目录不可写”“导出文件扩展名必须是 .md/.pdf”“报告快照不完整”或“报告导出失败”。

**场景与原因**：任务尚未生成报告；保存对话框选了错误后缀；目标目录不存在或无写权限；目标是符号链接/非普通文件；没有确认覆盖；任务报告快照损坏或旧任务缺少必要快照。

**处理**：先打开已生成报告的任务；在“另存为”中使用 `.md` 或 `.pdf`；选择用户有写权限的普通目录；若目标文件已存在，确认覆盖或换名。报告尚待人工复核时仍允许导出，但导出文件会保留“结论待定”标记。不要把导出目标放入任何任务快照目录。

**可恢复性**：路径和权限问题可恢复；导出失败不会覆盖已有目标，也不会修改原报告、数据库或任务状态。快照不完整时保留任务目录，先处理任务恢复问题。

**查看位置**：报告页错误 Message Bar、目标目录权限、任务目录中的 `report.md`/`report.json`/Rubric/审计快照和应用日志。

**求助信息**：导出格式、文件后缀、目标目录是否可写、任务状态、错误提示和是否已有目标文件。不要提供报告正文、论文或 Provider 响应。

## 14. PDF 中文乱码、页数异常或字体验证失败

**提示特征**：显示“无法确认中文字体”“生成的 PDF 不包含可抽取文本”“生成文件不是有效的 PDF”“生成的 PDF 不是 A4 纵向页面”或导出的 PDF 中文显示异常。

**场景与原因**：Windows 缺少可用的 Microsoft YaHei UI、Microsoft YaHei 或 SimSun 字体；导出被第三方 PDF 阅读器锁定；目标文件写入不完整；使用了旧的损坏 PDF 查看器缓存。

**处理**：确认系统至少安装一种受支持的中文字体；关闭占用目标文件的阅读器；换一个可写目录重新导出；用其他 PDF 阅读器打开测试。当前 PDF 生成与验证只读取本地 Markdown/快照，不调用模型或外部网络，也不需要 API Key。

**可恢复性**：通常可恢复。失败时临时文件会清理，已有目标保持不变。

**查看位置**：报告页错误信息、应用日志和目标目录文件大小。不要上传整份报告或包含论文证据的截图。

**求助信息**：Windows 缩放/字体安装情况、页数、错误提示、导出格式和任务状态。不要提供论文正文或原始 Markdown 内容。

## 15. 人工复核未完成、结论待定

**提示特征**：任务状态为“评测完成 · 待人工复核”；报告顶部提示仍有人工复核；显示“人工复核尚未完成，当前风险结论待定”。

**场景与原因**：AI 对政治方向/学术诚信等否决项产生疑似或无法判断结果，或独立专家面板出现无法判断；系统按设计先完成全部 AI 阶段，再等待人工处理。

**处理**：在报告页顶部的人工复核卡片逐项选择待办；查看论文页码、引文、外部证据和专家原因；填写复核人和理由后选择“确认成立/确认不成立”，人工面板待办选择“触发风险/未触发风险”。线下查重报告只能在理由中记录结论，当前版本不会读取或保存文件。全部待办处理后报告会本地刷新。

**可恢复性**：这是正常待办状态，不是评测失败。可随时关闭应用后重新打开任务；人工决定保存后不会再次调用模型。未完成时仍可查看和导出，但不得把待定风险结论当作确定结论。

**查看位置**：报告页人工复核卡片、任务状态、`human-rule-decisions.json`/`human-panel-decision.json`（如已生成）和应用日志。不要公开复核理由中的论文原文或检测报告内容。

**求助信息**：任务 ID、待办数量、待办类型、报告是否刷新、界面错误提示。不要提供论文、查重报告、API Key 或原始模型输出。
